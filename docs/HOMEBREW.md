# Homebrew distribution

Ttry releases native macOS archives for Apple Silicon and Intel. Each published
archive has a SHA-256 sidecar and build metadata tied to the tagged commit and
workflow run. The release workflow renders a formula using those checksums,
installs it on both architectures, and only then updates the public tap.

## User installation

```bash
brew install delaudio/tap/ttry
```

Upgrade and uninstall use normal Homebrew commands:

```bash
brew upgrade ttry
brew uninstall ttry
```

## One-time tap bootstrap

The short tap name `delaudio/tap` maps to the public
[`delaudio/homebrew-tap`](https://github.com/delaudio/homebrew-tap) repository.
Create it once with a `Formula/` directory, then configure this repository
with:

- a fine-grained `HOMEBREW_TAP_TOKEN` Actions secret that can read and write
  repository contents in `delaudio/homebrew-tap`;
- a repository Actions variable named `HOMEBREW_TAP_ENABLED` set to `true`.

Tagged releases require both values. A preflight verifies that the tap is
enabled, the token is present, and that it has push access before any archive
or GitHub release asset is built. This keeps the public Homebrew installation
path in lockstep with every published release.

## Publishing a release

1. Update the package version in `Cargo.toml` and `Cargo.lock`.
2. Run the standard quality gate from the README.
3. Tag the exact release commit with `v<semver>` and push the tag.
4. Wait for the `Release` workflow to publish and smoke-test the artifacts.

The workflow accepts release tags in the form `vMAJOR.MINOR.PATCH` with an
optional prerelease suffix, and rejects SemVer build metadata (`+...`). It also
rejects a tag whose version does not match `Cargo.toml`. Release archives and
formula checksums are generated by the same run, so the formula never uses
`sha256 :no_check`.

GitHub first publishes the versioned archives as a prerelease so the formula
can download the exact public release URLs. The tap is updated only after the
Homebrew smoke test passes, then the release is promoted to stable. If the
smoke test or tap update fails, delete the failed prerelease and its tag before
retrying; release assets are intentionally not overwritten in place.

For the first release:

```bash
git tag -a v0.1.0 -m "ttry v0.1.0"
git push origin v0.1.0
```
